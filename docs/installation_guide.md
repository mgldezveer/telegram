# Руководство по установке и запуску Telegram-бота

## Требования

- Python 3.8 или выше
- Docker и Docker Compose (опционально, но рекомендуется)
- Redis (для кэширования и хранения состояния)
- База данных (поддерживается SQLite, PostgreSQL)
- Telegram Bot Token (из @BotFather)

## Установка

### 1. Клонирование репозитория

```bash
git clone <repository-url>
cd telegram
```

### 2. Установка зависимостей

Создайте виртуальное окружение и установите зависимости:

```bash
python -m venv venv
source venv/bin/activate # На Windows: venv\Scripts\activate
pip install -r requirements.txt
```

### 3. Настройка переменных окружения

Создайте файл `.env` на основе `.env.example`:

```bash
cp .env.example .env
```

Отредактируйте файл `.env`, указав необходимые параметры:
- `TELEGRAM_BOT_TOKEN` - токен вашего Telegram-бота (получите от @BotFather)
- `ADMIN_IDS` - ID администраторов бота (через запятую)
- `DATABASE_URL` - строка подключения к базе данных (по умолчанию используется SQLite)
- `REDIS_URL` - URL для подключения к Redis (если используется)
- `GROQ_API_KEY` - API-ключ для Groq (рекомендуется, быстрый и с хорошими возможностями)
- `GEMINI_API_KEY` - API-ключ для Google Gemini (для высококачественного контента)
- `HUGGINGFACE_API_KEY` - API-ключ для Hugging Face (для резервного провайдера)

### 4. Инициализация базы данных

Для основной функциональности бота:
```bash
python init_db.py
```

Если используется autopost функциональность:
```bash
python init_autopost_db.py
```

## Запуск

### Запуск в режиме разработки

Для запуска основного бота:
```bash
python run.py
```

Для запуска автопостинг-бота (если используется отдельный бот для автопостинга):
```bash
python run_autopost.py
```

### Запуск с использованием Docker (рекомендуется)

Создайте или обновите файл `.env` с вашими настройками, затем запустите:

```bash
docker-compose up --build
```

Для запуска в фоновом режиме:
```bash
docker-compose up --build -d
```

### Запуск autopost функциональности

Для запуска автопостинг-бота отдельно:
```bash
python run_autopost.py
```

Или с помощью Docker Compose:
```bash
docker-compose up --build celery-worker
```

## Конфигурация Docker

Файл `docker-compose.yml` настраивает следующие сервисы:

- `bot` - основной бот-приложение
- `db` - PostgreSQL база данных
- `redis` - Redis для кэширования и хранения состояния
- `celery-worker` - воркер для фоновых задач
- `prometheus` - система мониторинга

Для настройки Docker-окружения:

1. Убедитесь, что Docker и Docker Compose установлены
2. Обновите `.env` файл с вашими настройками
3. Запустите `docker-compose up --build`

## Дополнительные команды

- `check_setup.py` - проверка корректности настройки
- `check_db.py` - проверка состояния базы данных
- `check_tasks.py` - проверка задач
- `clean_channels.py` - очистка каналов
- `sync_channel_stats.py` - синхронизация статистики каналов
- `add_test_analytics_data.py` - добавление тестовых данных аналитики
- `update_channel_username.py` - обновление имени пользователя канала

## Настройка LLM провайдеров

Бот поддерживает несколько провайдеров LLM:

1. **Groq** (рекомендуется) - быстрые ответы, хорошие возможности
2. **Google Gemini** - высококачественный контент
3. **Hugging Face** - резервный провайдер

Для каждого провайдера нужно указать API-ключ в `.env` файле. Бот автоматически переключается между провайдерами при сбоях.

## Настройка Redis

Redis используется для:
- Кэширования ответов LLM (снижает количество API-вызовов)
- Хранения состояния пользовательских сессий
- Ограничения частоты запросов

Для локального запуска Redis:
```bash
docker run -d --name redis -p 6379:6379 redis:7-alpine --maxmemory 512mb --maxmemory-policy allkeys-lru
```

## Возможные проблемы

### Проблемы с подключением к Telegram API

Проверьте, что токен бота указан правильно и у вас нет проблем с доступом к Telegram API.

### Проблемы с базой данных

Убедитесь, что строка подключения к базе данных указана корректно и у вас есть необходимые права доступа.

### Проблемы с Redis

Проверьте, что Redis запущен и доступен по указанному URL. Если Redis недоступен, бот автоматически использует встроенный кэш в памяти.

### Проблемы с LLM API

Убедитесь, что API-ключи указаны правильно и у вас есть доступ к соответствующим провайдерам. Проверьте лимиты использования API.

### Проблемы с Docker

Если возникают проблемы с Docker:
1. Убедитесь, что Docker и Docker Compose установлены
2. Проверьте, что порты 9090, 5432, 6379 не заняты другими процессами
3. Убедитесь, что у вас достаточно свободного места на диске

## Мониторинг и логирование

Приложение включает систему мониторинга:
- Метрики доступны по адресу: `http://localhost:9090/metrics`
- Проверка состояния: `http://localhost:9090/health`

Логи сохраняются в папку `logs/` при локальном запуске и в контейнер Docker при использовании Docker.

## Обновление

Для обновления до последней версии:

1. Обновите репозиторий:
```bash
git pull origin main
```

2. Обновите зависимости:
```bash
pip install -r requirements.txt
```

3. Примените миграции базы данных (если есть):
```bash
# Запустите скрипт инициализации базы данных заново

```

4. Перезапустите приложение.
